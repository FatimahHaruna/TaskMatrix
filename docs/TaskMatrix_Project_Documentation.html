1Project Overview

What is TaskMatrix?

TaskMatrix is a full-stack productivity web application built on the MERN stack. It implements the Eisenhower Matrix — a time-management method popularised by US President Dwight D. Eisenhower — which sorts every task into one of four quadrants based on urgency and importance:

QuadrantCriteriaAction
Q1 – Do FirstUrgent + ImportantHandle immediately
Q2 – ScheduleNot Urgent + ImportantPlan and schedule
Q3 – DelegateUrgent + Not ImportantHand off to others
Q4 – EliminateNot Urgent + Not ImportantDrop or defer

By forcing every task into one of these quadrants, TaskMatrix helps users immediately see what truly demands their attention versus what is just noise. The application layers AI-assisted quadrant suggestions, deadline tracking, team collaboration, analytics, and a personal journal on top of this framework.

The Problem It Solves

Modern students, professionals, and teams face an overwhelming volume of tasks with no clear way to prioritise. Email inboxes, calendar notifications, group chats, and todo lists all compete for attention. People end up working on whatever feels most urgent in the moment — often Q3 or Q4 tasks — while genuinely important Q2 work (long-term projects, skill development, thesis writing) never gets started.

TaskMatrix solves this by:

  • Forcing conscious categorisation of every task before it appears on the board
  • Using AI to suggest the correct quadrant so users cannot deceive themselves
  • Surfacing overdue tasks prominently and sending notifications
  • Providing real analytics so users see their own productivity patterns
  • Keeping each user's data completely private and isolated

Target Users

  • University students juggling coursework, internship applications, and social commitments
  • Individual professionals managing personal and work tasks in one place
  • Small teams who want to collaborate and share task ownership without a heavyweight tool like Jira

TaskMatrix follows a classic three-tier architecture:

6Phase 4 – Backend Development

A

Server Entry Point

server/server.js

The Express application was initialised with CORS enabled for the client origin, JSON body parsing middleware, and three route groups:

const app = express();
connectDB();
app.use(cors({ origin: process.env.CLIENT_URL || 'http://localhost:5173' }));
app.use(express.json());
app.use('/api/auth',  require('./routes/auth'));
app.use('/api/tasks', require('./routes/tasks'));
app.use('/api/ai',    require('./routes/ai'));
app.use(errorHandler);
B

Database Models

server/models/

User model key features:

  • The password field uses select: false so it is never accidentally returned in API responses
  • A pre('save') hook hashes the password with bcrypt only when it has been modified, preventing double-hashing
  • The comparePassword instance method wraps bcrypt.compare for clean controller usage
  • The isLocked virtual property computes lockout status from lockUntil

Task model key feature:

  • The owner field (ObjectId referencing User, with a database index) is the cornerstone of data isolation. Every query in the task controller filters by owner: req.user._id
C

Authentication System

server/controllers/authController.js

Registration

Validates password strength (8+ chars, uppercase, number, special character), checks for duplicate email, creates user, returns JWT.

Login

Checks lockout first. Compares password with bcrypt. On failure, increments loginAttempts using findByIdAndUpdate (not save()) to avoid triggering the password pre-save hook. On success, resets counters the same way.

🐛 Critical Bug Found & Fixed
The original implementation used user.save() to update login attempt counters. Because the password field was loaded into the document (via select('+password')), Mongoose's pre-save hook re-hashed the already-hashed password on every successful login. The next login attempt then failed because bcrypt.compare(plain, hash(hash)) always returns false. Fix: replaced all counter updates with User.findByIdAndUpdate(), which bypasses the pre-save hook entirely.

Password Reset

  1. forgotPassword: generates crypto.randomBytes(32) token, stores the SHA-256 hash in the database with a 1-hour expiry, returns the raw token to the client (in a real deployment this would be emailed)
  2. resetPassword: hashes the submitted token, queries the database for a matching unexpired record, sets the new password (triggering the bcrypt pre-save hook correctly), clears lockout fields
D

Task Management API

server/controllers/taskController.js

Every route handler begins with an owner filter:

// Example — getAll
const tasks = await Task.find({ owner: req.user._id, deleted: false })
  .sort({ order: 1, createdAt: -1 });

// Example — create
const task = await Task.create({ ...req.body, owner: req.user._id });

Soft deletion: tasks are marked deleted: true rather than removed. The Trash endpoint returns { deleted: true } records. permanentDelete removes the document entirely.

The toggleDone handler sets completedAt to the current timestamp when completing a task, which powers the real analytics heatmap and bar chart.

E

AI Integration

server/controllers/aiController.js

Three AI endpoints use the Anthropic Claude API:

  • /suggest — Given a task title and notes, returns the recommended Eisenhower quadrant with a brief explanation
  • /subtasks — Returns a checklist of 3–7 concrete subtasks for a given task
  • /misclassify — Compares the user's chosen quadrant against the AI suggestion; returns a warning if they differ (FR-413)

An in-memory cache (Map) prevents redundant API calls. Cache keys combine the task title and notes. Entries expire after 5 minutes and the cache is capped at 500 entries.

const aiCache = new Map();
const CACHE_TTL = 5 * 60 * 1000;
const CACHE_MAX = 500;

function getCached(key) {
  const entry = aiCache.get(key);
  if (!entry) return null;
  if (Date.now() - entry.ts > CACHE_TTL) { aiCache.delete(key); return null; }
  return entry.data;
}

7Phase 5 – Frontend Development

A

Application Bootstrap

main.jsx + App.jsx

main.jsx initialises dark mode from localStorage before React renders (prevents flash of wrong theme), then mounts the app inside AuthProvider → TaskProvider → BrowserRouter.

App.jsx defines all routes. A RequireAuth wrapper redirects unauthenticated users to /login. The root / and all unmatched paths (*) redirect to /login.

B

Context Providers

context/AuthContext.jsx + TaskContext.jsx

AuthContext manages the authenticated user object. On mount it checks localStorage for a guest record (tm_guest) or a JWT token (tm_token), then calls /api/auth/me to rehydrate the session. loginAsGuest() clears the JWT token first so API tasks cannot bleed through.

TaskContext imports AuthContext. When the user changes (login, logout, switch to guest), it either loads tasks from the API (authenticated users) or resets to an empty array (guests and unauthenticated). This was the fix that prevented guest users from seeing private account tasks.

useEffect(() => {
  if (!user || user.isGuest) {
    setTasks([]);  // empty — no seed data, no leaked API tasks
    setTrash([]);
    setUsingApi(false);
    return;
  }
  loadTasks();    // authenticated — fetch from API
}, [user?._id, user?.isGuest, loadTasks]);
C

Login Page

pages/LoginPage.jsx
  • Split layout: left brand pane (logo + Eisenhower card previews) + right form pane
  • Tabbed Sign In / Create Account (no page reload)
  • Password strength meter (0–4 score: length, uppercase, number, special character)
  • ForgotPasswordModal: two-step (email → new password). Token is managed entirely in React state — users never see or interact with the raw hex token.
  • Google OAuth button was removed because real OAuth credentials were not available; the button would silently log users in as Guest instead.
D

Board Page

pages/BoardPage.jsx + components/board/

The Board is the core feature. It renders four Quadrant columns inside a DragDropContext from @hello-pangea/dnd. Dragging a task card to a new column calls moveTask() which optimistically updates the UI then persists the new quadrant to the API.

A FilterPanel allows filtering by priority chips, label text, assignee (only "Me"), and due date windows. Active filters show as dismissible chips below the topbar. The filter count badge on the Filter button shows how many filters are active.

The ASSIGNEES array contains only { id: 'me', name: 'Me (you)' } — no hardcoded fake names. The team invite system populates real invited members if needed.

E

Analytics Page

pages/AnalyticsPage.jsx

All statistics derive from the real tasks array from TaskContext:

  • KPI cards: Completion rate, completed count, active count, overdue count — all calculated from actual task data
  • 14-day bar chart: For each of the last 14 days, counts tasks created and completed on that day using createdAt and completedAt timestamps
  • Quadrant distribution: Stacked bar and row chart from live task quadrant values
  • Productivity heatmap: Reads completedAt timestamps, groups by day-of-week (Mon–Sun) and hour (9am–5pm) to show when the user is most productive. Empty until the user completes their first task.
F

Journal Page

pages/JournalPage.jsx

A two-panel note-taking page built as a replacement for the "Personal" page. The left panel lists all entries (with search). The right panel shows the editor/viewer. Entries are stored in localStorage under tm_journal_<userId> so they are isolated per user. Each entry has an id, title, body, createdAt, and updatedAt.

G

Team Page

pages/TeamPage.jsx

Completely rewritten from a hardcoded demo. The invite flow:

  3. If the backend finds a matching user, their profile is returned
  4. The invited member is added to localStorage under tm_team_<userId>
  5. Roles are free-text with preset suggestions via <datalist>

Sidebar & Navigation

components/layout/Sidebar.jsx

8Errors & Problems Encountered

The following is a complete log of every significant error discovered during development, its root cause, and how it was resolved.

ERROR 1 — MongoDB Atlas Connection Refused (querySrv ECONNREFUSED)

Symptom

Server crashed on startup with querySrv ECONNREFUSED 8.8.8.8:53.

Cause

The MongoDB Atlas URI was used in the .env file, but the network environment did not allow outbound DNS/TCP to Atlas clusters on port 27017.

Fix

Switched to a local MongoDB instance (mongodb://localhost:27017/taskmatrix). User was guided to start MongoDB manually: "C:\Program Files\MongoDB\Server\8.3\bin\mongod.exe".

ERROR 2 — Vite Not Recognised / npm install peer dependency conflict

Symptom

'vite' is not recognized as an internal or external command when running npm run dev.

Cause

The client node_modules directory was not installed. A peer dependency conflict between React 18 and an older package prevented standard npm install from completing.

Fix

Ran npm install --legacy-peer-deps inside the client/ directory to bypass the strict peer dependency check.

ERROR 3 — App Loaded on /board Without Authentication

Symptom

Visiting / went directly to the board page without requiring login.

Cause

The root route / was mapped to BoardPage and the RequireAuth guard was not wired up correctly.

Fix

Changed / to redirect to /login. Added RequireAuth wrapper around all protected routes in App.jsx. Added a * catch-all redirect to /login.

ERROR 4 — Guest Session Showed Logged-in User's Private Tasks

Symptom

After clicking "Continue without account" while a user was already logged in, the guest session displayed all tasks from the authenticated account.

Cause

loginAsGuest() set the tm_guest key in localStorage but did not clear tm_token. The Axios interceptor still sent the JWT on every request, so the API returned the real user's tasks.

Fix

Added localStorage.removeItem('tm_token') to loginAsGuest(). Additionally, TaskContext was updated to reset tasks to an empty array when the user is a guest or unauthenticated.

ERROR 5 — Password Double-Hashing Bug (Critical Login Failure)

Symptom

Users could log in once after registration, but all subsequent login attempts failed with "Invalid email or password."

Cause

The login controller loaded the user document with .select('+password'), then called user.save() to update loginAttempts. Mongoose's pre('save') hook ran and re-hashed the already-hashed bcrypt string. The stored password became bcrypt(bcrypt(plaintext)). Future bcrypt.compare(plaintext, bcrypt(bcrypt(plaintext))) always returned false.

Fix

Replaced all user.save() calls in the login flow with User.findByIdAndUpdate(). This method bypasses the pre-save middleware entirely, so the password hash is never touched during counter updates.

ERROR 6 — Password Reset Had No Step 2 (Dead-End Flow)

Symptom

Clicking "Forgot password?" displayed a form, but after submitting the email, the modal only showed the raw hex token with a "Close" button. There was no way to actually set a new password.

Cause

The ForgotPasswordModal component was only half-implemented. Step 1 (email submission) called /forgot-password and displayed the returned token, but step 2 (setting the new password using that token) was never built.

Fix

Rewrote the modal as a true two-step flow. Step 1 requests the token. Step 2 hides the token in component state (users never see the hex string) and presents a new password field with the strength meter. On submit, calls /reset-password then auto-signs the user in.

ERROR 7 — Analytics Using Math.random() (Fake Data)

Symptom

The 14-day productivity chart and heatmap displayed different data on every page refresh and bore no relation to the user's actual tasks.

Cause

Chart data was generated with Math.random() as a placeholder during initial development and was never replaced with real data.

Fix

Rewrote both charts to derive data from the tasks array in TaskContext. The bar chart filters by task.createdAt and task.completedAt per day. The heatmap groups completions by day-of-week and hour from completedAt.

ERROR 8 — Hardcoded Team Members & Fake Workspace Items

Symptom

The Team page showed "Maya Chen", "Omar Hassan", and "Iris Kim" as permanent members. The sidebar showed "Spring '26 Semester" and "Senior Thesis" workspace sections. The board assignee filter listed these fake names.

Cause

These were copied from design mockups and left as static data in the components.

Fix

TeamPage was completely rewritten with a real invite system backed by GET /api/auth/search. Sidebar workspace sections were removed. The ASSIGNEES array was reduced to [{ id: 'me', name: 'Me (you)' }].

ERROR 9 — Seed/Demo Tasks Showing for New Users

Symptom

Every new user saw 8 pre-populated demo tasks ("Finish CS101 lab report", "Email Prof. Nguyen", etc.) on their first login.

Cause

The SEED array in TaskContext.jsx was used as the initial state for useState(SEED). It was also used as a fallback when the API was unreachable.

Fix

Deleted the entire SEED array. Changed the initial state to useState([]). The API fallback now also sets an empty array. New users see a clean empty board.

ERROR 10 — Sidebar Gap After Removing Workspace Section

Symptom

After removing the "Spring '26 Semester" and "Senior Thesis" workspace items, a large empty gap appeared in the middle of the sidebar between the main nav items and the bottom nav items.

Cause

The <div className="tm-sidebar-spacer"> element (CSS flex: 1) always existed to push bottom items to the bottom. When workspaces filled the space above it, it was less noticeable. With them gone, the spacer created a very visible dead zone.

Fix

Removed the spacer div. Wrapped the bottom nav items in a container div with style={{ marginTop: 'auto' }}, which achieves the same bottom-anchoring effect without a visible gap. Also reduced the Brand logo bottom padding from 18px to 8px.

ERROR 11 — Google OAuth Button Logged Users In as Guest

Symptom

Clicking "Continue with Gmail" silently logged the user in as a Guest account rather than authenticating via Google.

Cause

Real Google OAuth requires registration of the app in Google Cloud Console and a valid client_id. Neither was available, so the button was calling loginAsGuest() internally as a stand-in.

Fix

Removed the Google OAuth button and the "or with email" divider entirely. The login form now only offers email/password sign-in and account creation.

ERROR 12 — push Rejected (Remote Has New Commits)

Symptom

git push rejected with "Updates were rejected because the remote contains work you do not have locally."

Cause

Changes were committed on the remote branch (by a background agent or a parallel session) while the local branch was not up to date.

Fix

Used git fetch origin <branch> && git rebase origin/<branch> to replay local commits on top of the remote state, then pushed cleanly.

9Deployment Guide

The following steps cover deploying TaskMatrix to a production environment. The recommended stack is Render (backend API) + Vercel (frontend) + MongoDB Atlas (database), all of which have free tiers.

Step 1 — Prepare MongoDB Atlas

1

Create a free Atlas cluster

Go to mongodb.com/atlas → Create a free M0 cluster → Choose a region close to your users.

2

Create a database user

In Atlas → Security → Database Access → Add New Database User. Note the username and password.

3

Whitelist all IPs (for cloud hosting)

Security → Network Access → Add IP Address → 0.0.0.0/0 (allows any IP — fine for render.com deployments).

4

Get the connection string

Connect → Drivers → copy the URI. It looks like: mongodb+srv://username:password@cluster.mongodb.net/taskmatrix?retryWrites=true&w=majority

In server/.env (on Render), set:

CLIENT_URL=https://your-app-name.vercel.app

This ensures the CORS policy only allows requests from your frontend domain.

Running Locally (Development)

# Terminal 1 — Start MongoDB (Windows)
"C:\Program Files\MongoDB\Server\8.3\bin\mongod.exe"

# Terminal 2 — Start backend
cd server
npm install
npm run dev     # nodemon server.js on port 5000

# Terminal 3 — Start frontend
cd client
npm install --legacy-peer-deps
npm run dev     # Vite on port 5173
✓ Health Check
Once both servers are running, visit http://localhost:5000/api/health — it should return {"status":"ok"}. Then open http://localhost:5173 to use the app.
